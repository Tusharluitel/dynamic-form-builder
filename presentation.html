Response Flow — Guest Identity

Anonymous User Tracking

Problem: Anonymous users need a persistent identity to:

  • Resume in-progress drafts
  • Block duplicate submissions
  • Verify ownership on each AJAX save

Solution: Issue a 64-char hex cookie dfr_guest on first visit. Stored against the response in dynamic_form_response_sessions.

Token validated with regex before use — tampered or malformed values are silently regenerated.
Cookie is HttpOnly — not accessible from JavaScript. 
function _dynamic_form_response_get_guest_token() {

  // Validate existing cookie.
  // Reject anything that doesn't look like our token.
  if (!empty($_COOKIE['dfr_guest'])) {
    $token = $_COOKIE['dfr_guest'];
    if (preg_match('/^[a-f0-9]{64}$/', $token)) {
      return $token;
    }
  }

  // Generate a cryptographically-random 64-char token.
  $token = bin2hex(drupal_random_bytes(32));

  setcookie(
    'dfr_guest',
    $token,
    time() + 60 * 60 * 24 * 365,  // 1-year expiry
    '/',
    '',
    FALSE,
    TRUE   // HttpOnly flag
  );
  $_COOKIE['dfr_guest'] = $token;
  return $token;
}
Response Flow — Auto-save

Draft Persistence — _do_save()

Every field change triggers a debounced AJAX call. Server-side steps:

  1. CSRF token — drupal_valid_token()
  2. Verify form is open (opens_at / closes_at)
  3. Ownership check (auth: user_id / guest: guest_token)
  4. Create draft row on first save
  5. Link guest token in sessions table
  6. _upsert_answer() per field value
Draft row is created on first auto-save, not on page load — prevents orphaned rows from users who view but never type. 
// First save: create the draft response row
$response_id = db_insert('dynamic_form_responses')
  ->fields(array(
    'form_id'     => $form_id,
    'user_id'     => (int) $user->uid,
    'status'      => 0,          // 0 = draft
    'guest_email' => $guest_email,
    'created_at'  => $now,
    'updated_at'  => $now,
  ))->execute();

// Track guest identity in the sessions table
db_insert('dynamic_form_response_sessions')
  ->fields(array(
    'response_id' => (int) $response_id,
    'session_id'  => hash('sha256', session_id()),
    'guest_token' => $user->uid
                       ? NULL
                       : _dynamic_form_response_get_guest_token(),
    'created_at'  => $now,
  ))->execute();

// Upsert each answer — INSERT or UPDATE if already exists
foreach ($answers as $question_id => $value) {
  _dynamic_form_response_upsert_answer(
    (int) $response_id,
    $question_id,
    (string) $value,
    $now
  );
}
Response Flow — Final Submit

Submission — _do_submit()

Validation chain before marking submitted:

  1. CSRF token check
  2. Anonymous users: public forms only
  3. Ownership — auth: user_id / guest: guest_token
  4. All required questions must have answers
  5. SET status=1, submitted_at=NOW()
  6. Trigger Solr indexing
index_response() is called after the DB write commits — Solr always reflects the final submitted state. 
// Guest ownership check against sessions table
$guest_token = _dynamic_form_response_get_guest_token();
$match = db_select('dynamic_form_response_sessions', 's')
  ->condition('response_id', $response_id)
  ->condition('guest_token', $guest_token)
  ->countQuery()->execute()->fetchField();
if (!$match) {
  return array('status'  => 'error',
               'message' => t('Access denied.'));
}

// Validate all required fields have answers
$missing = array();
foreach ($required as $qid => $q) {
  if (empty($answer_map[$qid])) {
    $missing[] = check_plain($q->label);
  }
}
if (!empty($missing)) {
  return array('status'  => 'error',
               'message' => t('Required: @fields',
                 array('@fields' => implode(', ', $missing))));
}

// Mark as submitted
db_update('dynamic_form_responses')
  ->fields(array('status'       => 1,
                 'submitted_at' => REQUEST_TIME))
  ->condition('id', $response_id)->execute();

// Hand off to Solr (called after DB commits)
dynamic_form_solr_index_response($response_id);

Solr — Document Schema

Field Naming — _build_response_doc()

No fixed Solr schema. Field names are prefix-typed per question:

is_Integer storedresponse_id, form_id
ds_Date storedsubmitted_at (ISO 8601)
tm_Text multiFull-text search answers
sm_String multiExact match + facetable
ss_String singleRadio / single-select

Each question maps to tm_q_{id} or sm_q_{id}.

Adding a new question type requires zero Solr schema changes — the prefix system covers all cases. 
// Base document fields
$doc = array(
  'id'             => 'response-' . $response->id,
  'doc_type'       => 'response',
  'is_response_id' => (int) $response->id,
  'is_form_id'     => (int) $response->form_id,
  'ds_submitted_at'=> gmdate('Y-m-d\TH:i:s\Z',
                              $response->submitted_at),
);

// Map each answer to a prefix-typed dynamic field
foreach ($answers as $a) {
  $type = $question_types[$a->question_id];
  $key  = 'q_' . $a->question_id;

  if (in_array($type, array('text','textarea','text_editor'))) {
    // Full-text searchable field
    $doc['tm_' . $key] = strip_tags($a->value);
  }
  elseif ($type === 'tags') {
    $tags = json_decode($a->value, TRUE);
    $doc['tm_' . $key] = $tags;   // full-text
    $doc['sm_' . $key] = $tags;   // exact + facets
  }
  else {
    // Checkbox, radio, select, etc.
    $doc['sm_' . $key] = $a->value;
  }
}

// Catch-all search field — all text merged
$doc['tm_answers'] = array_unique($tm_answers);
Solr — Search and Filter

Filtering Responses — filter_responses()

The read pipeline:

  1. UI criteria passed to build_criteria_params() → builds fq= filter clauses
  2. _fetch_response_ids() queries Solr /select
  3. Returns Drupal response IDs only — actual data still fetched from MySQL

Tag autocomplete uses:

  • search_tags() — exact prefix match
  • fuzzy_search_tags() — typo tolerance
Solr is the search layer only — it never replaces MySQL as the source of truth. Keeps data consistent. 
function _dynamic_form_solr_fetch_response_ids(
    $form_id, $q, array $fq = array()) {

  $params = array(
    'q'    => $q ?: '*:*',
    'fq'   => array_merge(
      array(
        'doc_type:response',
        'is_form_id:' . (int) $form_id,
      ),
      $fq   // additional filter clauses from UI
    ),
    'fl'   => 'is_response_id',  // return only IDs
    'rows' => 10000,
    'wt'   => 'json',
  );

  $url    = variable_get('dynamic_form_solr_url', '')
          . '/select?' . http_build_query($params);
  $result = _dynamic_form_solr_request($url);

  if (empty($result['response']['docs'])) {
    return array();
  }

  // Return plain array of response IDs
  return array_column(
    $result['response']['docs'],
    'is_response_id'
  );
}

Batch API runs chunks independently — PHP memory stays constant regardless of export size. JSONL is the intermediate format because each chunk can append independently.
Export — Batch Processing

Chunked Query — _responses_process()

Key decision: Load all answers for the current chunk in one IN query — not N+1 queries.


  1. Query 50 responses with range($offset, 50)
  2. Collect their IDs → single IN (ids...) for answers
  3. Key answers as $answers[response_id][question_id]
  4. Format each cell via format_answer()
  5. Append to .jsonl with FILE_APPEND|LOCK_EX

Without IN query: 1000-response export = 1001 DB queries.
With IN query: 1000-response export = 21 DB queries. 
// 1. Fetch chunk of 50 responses
$responses = $q->range($offset, $batch_size)
               ->execute()->fetchAll();

// 2. Collect IDs, load ALL answers in ONE query
$response_ids = array_map(
  function ($r) { return (int) $r->id; }, $responses
);
$answer_rows = db_select('dynamic_form_answers', 'a')
  ->fields('a', array('response_id','question_id','value'))
  ->condition('a.response_id', $response_ids, 'IN')
  ->execute()->fetchAll();

// 3. Key answers as [response_id][question_id] = value
$answers = array();
foreach ($answer_rows as $ar) {
  $answers[(int) $ar->response_id]
          [(int) $ar->question_id] = $ar->value;
}

// 4. Build + append one JSON line per response
$lines = '';
foreach ($responses as $r) {
  $row = array($timestamp, $email, $name);
  foreach ($question_ids as $qid) {
    $raw   = isset($answers[$r->id][$qid])
             ? $answers[$r->id][$qid] : '';
    $row[] = _dynamic_form_export_format_answer($raw, $type);
  }
  $lines .= json_encode($row) . "\n";
}
file_put_contents($temp_file, $lines, FILE_APPEND | LOCK_EX);
Export — Final Conversion

JSONL → XLSX — _responses_finished()

Why JSONL as intermediate?

  • Each batch chunk appends independently
  • No shared in-memory state between chunks
  • Conversion to XLSX happens exactly once at the end

OpenSpout writes XLSX row-by-row via streaming — never loads the full file into memory at once.

Header row is styled bold via Style::setFontBold().
Temp folder is set so OpenSpout doesn't overflow /tmp. 
require_once DRUPAL_ROOT
  . '/sites/all/libraries/openspout/autoload.php';

// Configure writer — use our own temp folder
$options = new \OpenSpout\Writer\XLSX\Options();
$options->setTempFolder(_dynamic_form_export_temp_dir());

$writer = new \OpenSpout\Writer\XLSX\Writer($options);
$writer->openToFile($xlsx_path);

// Bold style applied to header row only
$header_style = (new \OpenSpout\Common\Entity\Style\Style())
  ->setFontBold();

// Stream JSONL → XLSX, one line at a time
$handle   = fopen($results['temp_file'], 'r');
$is_first = TRUE;

while (($line = fgets($handle)) !== FALSE) {
  $cells = json_decode(trim($line), TRUE);
  if (!is_array($cells)) { continue; }

  $writer->addRow(
    \OpenSpout\Common\Entity\Row::fromValues(
      $cells,
      $is_first ? $header_style : NULL
    )
  );
  $is_first = FALSE;
}

fclose($handle);
$writer->close();
@unlink($results['temp_file']);  // clean up temp JSONL

Key Technical Decisions


Guest Identity via Cookie Token
64-char cryptographic token (dfr_guest) issued on first visit, validated against dynamic_form_response_sessions — enables duplicate blocking and draft recovery for anonymous users without Drupal sessions.
Solr Dynamic Field Naming (prefix typing)
Field names carry their own type prefix (tm_, sm_, ss_, is_) — no Solr schema migration ever needed when new question types are added.
Batch API + JSONL → XLSX Pipeline
Drupal Batch API processes 50 responses per chunk → appends to a JSONL temp file → single OpenSpout streaming pass converts to XLSX. PHP memory stays constant regardless of export size.
N+1 Query Prevention
All answers for a batch chunk are loaded in one IN (ids) query and keyed in PHP — reduces 1000-response export from 1001 queries to 21.
